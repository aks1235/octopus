# 全局模型过滤改为排除语义

## Goal

设置项 `model_filter`(全局模型过滤)从「命中保留」(白名单)改为「命中排除」(黑名单),对齐用户对"过滤"一词的直觉——全局层的常见用途是拦 embedding/rerank/搜索类垃圾模型,黑名单才顺手。**渠道级 `match_regex` 保持白名单不变**(渠道层常见用途是"该渠道只要这几个模型")。

## Background(2026-09-17 用户反馈)

- 用户在全局过滤填了正则,预期命中即排除,实际是命中才保留,结果只留下了想排除的模型。
- 现状实现:`internal/server/handlers/channel.go` fetch-model 路径的 `matches()`——两层正则取 AND,命中→保留;设置页 hint 只说「同时生效(AND),留空不过滤」,未说明命中语义,误导为排除。
- 生产核实(2026-09-17):`model_filter` 为空、渠道级 `match_regex` 全库 0 使用——改语义零存量风险。

## Requirements

- R1 全局过滤改为**命中排除**:模型名命中 `model_filter` 正则 → 该模型不进入拉取结果;不命中 → 保留。渠道级 `match_regex` 语义不变(命中保留),两层 AND 组合关系不变(都非空时模型须「通过渠道白名单 且 未被全局黑名单命中」)。
- R2 设置页 hint 写明语义:「命中排除」;渠道编辑器 match_regex 提示如有,写明「命中保留」;i18n 三语。
- R3 语义归属定位清晰:两层语义相反是有意设计(各按其层的常见用途),在 spec 里写明,防止后人"顺手统一"。
- R4 手工填写的模型不受影响(现状即如此,过滤只作用于拉取列表路径)。

## Non-goals

- 不做白名单/黑名单模式开关(YAGNI,语义固定后配置面不变)。
- 不改渠道级 match_regex 语义。
- 不动 member_regex(分组成员正则,另一套语义,命中纳入)。

## Acceptance Criteria

- [ ] AC1 设置 model_filter 后拉取模型列表:命中正则的模型不出现,其余保留
- [ ] AC2 两层同时配置:渠道白名单 ∩ 全局黑名单之外 = 最终结果(单测断言)
- [ ] AC3 model_filter 留空:行为与现在完全一致
- [ ] AC4 设置页与渠道编辑器的过滤提示文案三语齐全且语义表述明确
- [ ] AC5 octopus-verify 通过(自动关卡;UI 变更仅文案,人审从简)
