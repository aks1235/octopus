## Requirements

### R1 渠道健康检查+失败自动禁用(①重想象)

- 定时探测所有 enabled 及自动禁用状态的渠道(复用 /models 探测逻辑,含代理),间隔与失败阈值为可配置设置项,间隔设 0 可关闭
- 探测范围:渠道全部启用凭据 × 已配置协议端点,**任一成功即健康**(宽容判定,多 KEY 渠道剩一个活 KEY 不误杀)
- 连续失败达阈值:自动禁用渠道(enabled=false + auto_disabled=true),运维可见失败原因与最近检查时间
- 探测成功:失败计数清零;仅对「自动禁用且未启用」的渠道自动解禁,不误翻人工禁用的渠道
- 运维手动启停渠道即接管:清除 auto_disabled 标记
- 渠道列表/详情可见健康状态(失败次数、最近错误、最近检查时间、自动禁用标记)

### R2 分组正则成员(③重做)

- 分组可定义成员匹配正则(可选;regexp2 语法与渠道 match_regex 一致)
- 定义后:自动把**所有渠道中模型名匹配该正则的全部授权**纳入成员(同渠道同模型多凭据时全部纳入)
- 渠道模型新增且匹配 → 自动入组;渠道/模型删除或失配 → 自动移除(删除场景外键级联天然覆盖,重算兜底)
- 触发:渠道创建/更新/删除/启停后即时重算 + 启动时 + 定时兜底
- 无正则的分组(含迁移脚本带入的全部存量分组)行为完全不变;上游编辑器 autoAdd(子串匹配一键添加)交互对手动组保持原样
- 正则分组的成员列表在 UI 上只读(成员由正则决定,手动增删会被重算覆盖,故不允许);保留一键吸纳交互(衔接上游 autoAdd 习惯)

### R3 ②⑤ 原生覆盖验证

- 容器实测并留档:删渠道 → 分组成员级联消失;分组页渠道名/已禁用态正确展示

### R4 文档与任务地图

- 任务4(`09-08-v2-feat-log-persistence`)prd 增加交付物:渠道调用详情页(对照 `f551b95`)
- 父任务 `09-08-dev-v2-redo` prd 任务地图同步

## 约束

- 不追上游(ADR-0001);遵循 v2 现有代码风格(中文注释、结构体字段注释、op/handler 分层)
- 兼容存量:新列经 AutoMigrate 增量添加、零值默认,存量分组/渠道行为不变
- 对迁移演练的影响:零——channels/groups 新列无需脚本预填(健康状态首轮探测自然填充,member_regex 空=手动组),转换脚本产出库直接兼容
- 每步保持可独立构建起容器(父任务 AC)
