# 日志指标:分阶段速率 + 首字格 + 全格提示

## Goal

三处日志指标改进(用户 2026-09-20 提出):
1. **实时速率分阶段**:现在思考期恒为空(思考增量不计入字符量),长思考模型整段思考都没有速度显示;改为按相位分段显示。
2. **新增首字时间格**:数据已有(`first_token_ms`),只差展示。
3. **所有指标格补 hover 提示**:目前只有 2 格有提示,「缓存写入」(倒数第二格)等格子无文字标签、含义不明。

## Background(已实测确认)

- 复现证据:带思考的流式请求,t+1.5s~12.4s 期间 `phase=thinking` 且 `output_chars/output_speed` 为空 → 卡片速率格显示 `-`(用户视为"空"),进入正文后才出现数字。
- 根因是设计取舍(R3:思考增量不计入字符量),对长思考模型(reasoning_tokens 动辄数千)不可用。
- 上游做法(参考):按**事件个数**每事件 +1 计字符、不分阶段,故思考期也有数字,但数字是事件速率而非真实字符速率(与文本长度脱钩,且其 #398 修过 +2 虚高的 bug)。**我们不照搬其口径**,只借"思考期也要有数字"这一诉求。
- 现有指标行(卡片与详情共用 `LogMetrics`):时间 / Key / 耗时 / 费用 / 输入 / 缓存命中 / 输出 / 缓存写入 / 速率(9 格);仅 Key 与速率有 `title`。

## Requirements

- R1 **分阶段速率**:维护"当前相位内的字符数与计时起点";相位切换(思考→正文)时**重新计时**。
  - 思考期显示「思考 N c/s」(思考增量字符计),正文期显示「输出 N c/s」(正文增量字符计),完成后仍显示既有精确 `tok/s`(口径不变)。
  - 状态字段建议:`phase_chars`(当前相位已产出字符数)与 `phase_started_at`(当前相位起点);或等价的 (thinking_chars, output_chars) + 相位起点。字段名与形状由实现定,但**前端契约要与后端 JSON tag 一致**。
  - 相位尚未定出(未识别)时保持空/`-`(与现状一致)。
- R2 **首字格**:展示首字时间(`first_token_ms`,毫秒,人类可读如 `723ms` / `1.2s`);进行中且尚未有首字时显示 `-`;非流式按既有语义(首字=取得完整响应时刻,展示即可)。
- R3 **全格提示**:每个指标格补 `title`(hover 提示),文案 i18n 三语。至少覆盖:输入(扣除缓存命中后的输入 token)、缓存命中、输出、缓存写入、速率、首字、耗时、费用、时间、API Key。文案要**一句话说清含义**,例如:
  - 缓存命中:「命中提示缓存的输入 token 数(不重复计费的部分)」
  - 缓存写入:「本次请求写入提示缓存的 token 数」
  - 速率:「进行中按当前阶段(思考/输出)的字符速度;完成后为输出 token 速度」
- R4 不改既有 `tok/s`(完成后)口径(与历史面板一致);不改紧凑/调试两档与 memo 防重建;不动历史面板布局(仅补同样的提示与首字若适用)。

## Non-goals

- 不照搬上游按事件计数的口径。
- 不改后端结算/统计语义(相位字符量仅用于展示)。
- 不做指标格的自定义/隐藏配置。

## Acceptance Criteria

- [ ] AC1 长思考流式请求:思考期速率格显示「思考 N c/s」并在思考期间持续更新;进入正文后切为「输出 N c/s」且计时重置(数字反映正文阶段真实速度)
- [ ] AC2 完成后仍显示与历史面板一致的精确 `tok/s`
- [ ] AC3 首字格有值(`723ms` 形态),进行中未出首字时为 `-`
- [ ] AC4 每个指标格 hover 都有含义提示,三语齐全
- [ ] AC5 既有功能零回归(相位徽标、简洁/调试两档、memo 防心跳重建、缓存率展示)
- [ ] AC6 octopus-verify 通过(UI 人审:思考期有数字、切换后重置、首字有值、hover 提示可读)
