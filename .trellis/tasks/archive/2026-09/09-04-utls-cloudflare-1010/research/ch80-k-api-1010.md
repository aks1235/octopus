# ch80 (K API) Cloudflare 1010 根因和修复路径

## 问题确认

**时间**: 2026-09-04 16:24:40  
**渠道**: ch80 `K API | 默认分组 group (auto)`  
**域名**: `https://new.xkool.cfd/v1`  
**错误**: Cloudflare Error 1010 (browser_signature_banned)

```json
{
  "error_code": 1010,
  "error_name": "browser_signature_banned",
  "detail": "The site owner has blocked access based on your browser's signature.",
  "zone": "new.xkool.cfd"
}
```

## 当前状态（数据库）

```sql
-- ch80 完整配置
SELECT id, name, base_urls, utls, enabled FROM channels WHERE id = 80;
```

```
id:         80
name:       K API | 默认分组 group (auto)
base_urls:  [{"url":"https://new.xkool.cfd/v1","delay":0,"type":0,"provider_id":"openai-chat"}]
utls:       0  <-- ❌ 关闭,被 Cloudflare JA3 指纹拦截
enabled:    1
```

## 修复步骤（代码实现完成后）

### 1. 更新 ch80 开启 uTLS

```sql
UPDATE channels SET utls = 1 WHERE id = 80;
```

### 2. 重启容器（应用新 uTLS 代码）

```bash
cd /home/yuan/docker/octopus-new
docker compose down
docker compose up -d
```

### 3. 验证请求（通过前端或 curl）

预期：
- ✅ 不再报 1010 错误
- ✅ 请求成功转发到 new.xkool.cfd
- ✅ 日志显示 `relay complete: channel=80(K API), success=true`

### 4. 日志检查点

```bash
# 实时监控
docker compose logs -f | grep "K API"

# 查 relay_logs 确认成功
python3 <<'EOF'
import sqlite3
db = sqlite3.connect('data/data.db')

    SELECT time, channel_id, channel_name, use_time, error

```

## 其他可能需要开 uTLS 的渠道

同样被 Cloudflare 保护的域名渠道（需要类似处理）：
- 查询方式: `SELECT id, name, base_urls FROM channels WHERE base_urls LIKE '%cloudflare%' OR base_urls LIKE '%.cfd%'`
- 按需开启 `utls=1`
