# 故障转移语义对齐 v1:请求内游标 + 轮询模式回归

## Goal

把 v2 failover 的选路语义从「失败后从队头重扫、谁恢复谁插队」改为 v1 的「**请求内向下走的游标**」,并搬回 v1 的**轮询模式**;顺带把故障转移遍历改为**渠道主序**。解决用户体感「故障转移、分组不顺手」的两处根因。

## Background(2026-09-15/16 讨论定稿,用户逐条确认)

- 现状 `internal/relay/route.go pickGroupItem`:成员失败 → `CurrentItemID=0` → 下一轮从最高优先级重扫。成员多、冷却短时,同一请求反复回头撞刚失败的高优先级渠道(2026-09-15 日志实证:单请求 111 次尝试,K API 渠道被打 12 轮)。
- v1(`v1.5.3 internal/relay/balancer/`)有四种模式:RoundRobin/Random/Failover/Weighted,纯函数 `Candidates(groupID, items)`,另有 circuit.go 熔断(指数退避)。v2 只剩 manual/failover,轮询/随机/加权蒸发,用户主要用**轮询+故障转移**。
- v2 成员=授权(渠道×模型×凭据),failover 平铺遍历,111 次风暴里把每个模型变体×凭据组合全撞一遍——该按渠道先换。

## Requirements(语义,用户 2026-09-16 已拍板)

- R1 **请求内游标(failover 模式)**:单个请求内维护按优先级**向下走**的游标;冷却只做闸门(走到谁谁在冷却就跳过继续向下);走到末尾**绕回头部**继续;高优先级成员中途恢复**不插队**,等游标绕回。
- R2 **全员冷却**:游标绕完一整圈全员都在冷却 → **维持现状行为**:按既有 retry-interval 等待并重试,冷却到期后游标自然继续。**不新增等待上限、不新增报错终态**(2026-09-16 用户纠正:等待语义跟之前一样,勿加戏)。
- R3 **跨请求亲和保留**:v2 现有的亲和窗口语义不变(故障切备用成功后,窗口内新请求留在备用)。新请求游标起点=亲和窗口内的当前成员,无亲和则从最高优先级起。
- R4 **轮询模式回归**:GroupMode 增加 roundrobin(v1 语义:per-group 计数器循环);UI 分组模式选择器加回。随机/加权**不做**(用户未用,YAGNI)。
- R5 **渠道主序遍历**:failover/轮询的候选序列按「渠道(优先级序)→ 渠道内成员(自然序)」组织;一个渠道的多凭据/多模型变体视为同渠道块,渠道内失败先轮换块内成员,块内全败才换下一个渠道。
- R6 探测(probe)语义在游标模型下重审:游标走到已恢复成员即正常服务,单请求探测限流是否保留由 design 定(倾向保留跨请求防雷群,去掉请求内的)。
- R7 兼容:manual 模式零变化;现有 relay_config 六旋钮语义不变;不破坏 group_channel_orders 排序(游标顺序=priority 合成顺序)。
- R8 后端为主 + 前端模式选择器;无 schema 破坏性变更(Group.Mode 新枚举值,存量库无影响)。
- R9 **客户端中止不计失败**(2026-09-16 用户报告并入):取消轮次不追加 `AttemptFailed`(append 移到 ctx 取消检查之后);流式中途取消不写 `RequestFailed` 渠道统计(加 `ctx.Err()==nil` 条件)。中止不得污染日志 attempts、渠道统计与(现状本就不受影响的)冷却。

## Non-goals

- 不做 Random/Weighted 模式。
- 不动手动分组与吸纳。
- 不做熔断指数退避替换固定冷却(观察游标语义落地后再定,记在 spec 已知问题里)。
- 不动健康检查自动禁用/解禁。

## Acceptance Criteria

- [ ] AC1 单请求内游标向下:构造 10 成员、前 5 冷却的场景,请求从 #6 起,#6 失败后走 #7 而非跳回 #1;#1 中途恢复不插队
- [ ] AC2 绕圈回炉:#10 失败后回头,#1 已过冷却则服务 #1,未过则继续向下
- [ ] AC3 全员冷却:请求保持等待(与现状一致的 retry-interval 循环),最早到期后游标从该成员继续;无新增上限/报错
- [ ] AC4 亲和保留:故障切备用+成功后,窗口内新请求仍从备用起(既有测试回归)
- [ ] AC5 轮询模式:同组连续请求按成员(渠道块)循环,per-group 计数器隔离;UI 可选可选回
- [ ] AC6 渠道主序:多凭据/多模型变体渠道块内先轮换,块内全败才换渠道(复现 111 场景的用例收敛为按渠道计数)
- [ ] AC7 manual 模式、group_channel_orders 排序、既有旋钮零回归
- [ ] AC7b 客户端中止(首帧前取消/流式中途取消)→ 无 AttemptFailed 记录、无 RequestFailed 统计、无冷却
- [ ] AC8 octopus-verify 全流程通过(UI 人审必做:游标行为、轮询分布、模式切换)
