# 分组可用性:成员级测试 + 冷却重置

## Goal

分组页新增两个能力,解决两个真实痛点(证据见 Background):

1. **成员级连通性测试**:一键对分组内全部成员(渠道授权 = 渠道 × 模型 × 凭据)发起最小真实请求,逐成员报告能用/不能用,测通的成员立即清除冷却。
2. **冷却重置**:一键清空分组的全部成员冷却,不再"改完配置干等 10 分钟"。

## Background(2026-09-24 生产现场)

- 天翼云渠道 Anthropic 端点 401(授权协议位误含 anthropic),真实请求全部失败并进入冷却;
  面板渠道 key 测试因"任一协议成功即判通过"显示绿色(`internal/relay/keytest.go:34`),
  用户无从知道"分组里哪个成员真正能用",只能等真实流量把坏成员打进冷却才暴露;
- 成员冷却最长到封顶值(默认 600s,指数退避),修好配置后无任何入口提前恢复,唯一手段是重启容器(丢内存统计)。

## Requirements

### R1 分组成员级测试

- R1.1 分组卡片提供"测试"入口,触发后对该分组**全部成员**逐个发起最小真实请求(非流式、`max_tokens=1`,与渠道 key 测试同口径)。
- R1.2 每个成员按其授权的**实际协议位**试测,顺序与渠道 key 测试一致(共用 `keyTestProtocols`:message → responses → chat);只有 chat 就只测 chat,只有 message 就只测 message,多位都有则按此顺序逐个测。**任一协议成功即停止该成员后续协议的试测**(省时省计费),并在结果中标注成功所用的协议。
- R1.3 测试**成功**的成员:立即清除其冷却(`cooldowns` + `trips`)并释放其探测占用,路由状态经 SSE 实时发布,前端冷却徽标即时消失。
- R1.4 测试**失败**的成员:不动路由状态;失败原因摘要(含各协议失败汇总)在界面上可见。
- R1.5 不可用成员(渠道/凭据被禁用或授权两侧缺失)不发起上游请求,直接报告"不可用"及原因,不产生计费。
- R1.6 每次真实发往上游的请求照写转发日志(日志页可回放试了哪些协议端点),客户端标识须能与渠道 key 测试、真实转发区分。
- R1.7 测试仅由人工在界面触发(真实计费),进行中禁止重复触发;客户端断开/取消时剩余成员不再发往上游。
- R1.8 手动模式与正则分组的成员测试同样适用(成员可用性与选择模式无关)。

### R2 冷却重置

- R2.1 分组卡片提供"重置冷却"入口,清空该分组**全部成员**的冷却与连续冷却计数,并释放探测占用。
- R2.2 当前路由(`current_item_id`)、亲和窗口与轮询计数器**不受影响**:重置只恢复候选资格,不强制切换流量。
- R2.3 重置后路由状态经 SSE 实时发布,前端徽标即时消失。
- R2.4 手动模式分组冷却本就不适用,不提供该入口。

### 通用

- R3.1 纯新增 API 端点,不改变任何既有端点行为与请求/响应形状(向后兼容)。
- R3.2 测试结果响应逐成员给出:成功与否、成功协议、失败原因、耗时、是否清了冷却。

## Non-goals

- 不改渠道级 key 测试的"任一协议成功即通过"判定(其语义是凭据连通性;分组测试测的是成员整体可用性,失败协议明细经 R1.4 暴露)。
- 不做定时自动测试/自动巡检(仅人工触发)。
- 不做单成员单独测试入口(整组测试已覆盖逐成员结果;后续有需要再加)。
- 不动健康检查(auto_disable)链路——那是渠道级探测,与本任务的成员冷却是两套状态。

## Acceptance Criteria

- [ ] AC1 复现场景:分组内某成员因上游 401 进入冷却 → 修好渠道配置 → 点"测试" → 该成员结果为成功且冷却徽标消失,下一次真实请求可立即选回该成员(无需等冷却到期、无需重启)。
- [ ] AC2 测试结果逐成员可见:成功(含所用协议)、失败(含原因摘要)、不可用(含原因);测试期间按钮有进行中状态,不可重复触发。
- [ ] AC3 日志页能看到分组测试产生的日志,客户端标识可区分于渠道 key 测试与真实转发。
- [ ] AC4 分组存在未到期冷却时点"重置冷却":全部成员的冷却徽标消失(SSE 实时),当前承载成员与亲和状态不变。
- [ ] AC5 手动模式分组:测试可用;重置冷却入口不出现。
- [ ] AC6 不可用成员不产生上游请求与计费,结果中给出原因。
- [ ] AC7 `go test ./internal/...` 全绿;web lint + build 通过;octopus-verify 全流程通过并写 marker。
