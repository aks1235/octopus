# ADR-0003: 多 URL 不移植

- 状态: 已接受(2026-09-08)

## 背景

fork 渠道模型为 `BaseUrls[]`(每 URL 独立类型,`internal/model/channel.go:23`)。上游 v0.13.2 为单 `BaseURL` + 多 KEY 表,且两度表态不做多 URL(2026-08-14 revert 多URL多KEY方案,2026-09-01 重做仅做 KEY)。

2026-09-08 实查生产库(`data/data.db`):113 个渠道中多 URL 渠道 **0 个**。

## 决策

- 不在 dev-v2 重新实现多 URL,也不做渠道拆分/克隆工具
- 数据迁移时每个渠道直接取其唯一 URL

## 后果

- 渠道模型与上游保持一致,后续升级无此块冲突成本
- 若未来真需要多 URL,用「多渠道+分组负载均衡+failover」原生表达
